opencode-deveco

在标准 opencode 里，用上华为 DevEco Code 的模型

把 DevEco Code 的模型（GLM-5.3 / GLM-5.1 / 视觉模型）无侵入地接进 opencode、Claude Code 与任何 OpenAI 兼容客户端 —— 一条本地代理，一个端口。

1

核心能力

🔌 双协议对外

同时提供 OpenAI 兼容端点与 Anthropic 原生端点，流式、非流式、工具调用、 思考块、图片往返完整转换，opencode 与 Claude Code 共用同一条代理。

🖼️ 识图自动路由

文本模型收到图片会被上游拒绝，代理透明改道视觉模型并把答案带回。 判定跟随云端 input_modalities，上游上新模型无需改代码。

🧠 思考不混进正文

思考走独立通道：OpenAI 侧返回 reasoning_content，Anthropic 侧返回标准 thinking block；历史里的残留自动清理，多轮不再累积污染。

🎚️ 思考档位如实生效

云端声明的档位（low/high/max）成为客户端可选项，默认档随请求下发； 越界档位就近映射，思考级别永远如实回传、不擅自篡改。

🔄 模型目录自动同步

云端目录落盘并在启动时注入：新增模型、上下文长度、思考档位、模态自动跟上， 小模型的选择也跟随云端声明。

🚦 串行排队与限流保护

上游按账号限并发，代理默认单并发 FIFO 排队：队列有上限、超出回 429 让调用方退避，放行前冷却，长回合不饿死后续请求。

🛡️ 崩溃防护与守护

客户端断连即取消上游、异常不带走进程、并发槽位不泄漏； 守护进程按退避自动重启，附 Linux / macOS / Windows 自启动脚本。

🧭 边界对齐官方

区域、账号、实名三道门禁与官方客户端一致，给出可读原因而不是上游超时； 已实名账号零额外开销，登录与刷新带竞态护栏。
